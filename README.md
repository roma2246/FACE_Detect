# EmoCam — распознавание эмоций по лицу с эмодзи

Веб-приложение: вы видите себя с веб-камеры, а над головой появляется эмодзи вашей эмоции.
Распознаются 5 эмоций: 😊 Happy, 😢 Sad, 😡 Angry, 😮 Surprise, 😐 Neutral.

Дополнительно — три жеста рукой: знак мира → ✌️, «коза» → 🎸, помахать раскрытой ладонью → 👋 «Привет!».
Точки руки находит готовая модель MediaPipe HandLandmarker, а сам жест определяется геометрическими
правилами в `front/src/lib/gestures.js` (какие пальцы выпрямлены; для махания — качание ладони
влево-вправо). Отдельная модель для жестов не обучалась.

## Как это работает

1. Браузер получает видео с камеры и находит лица (MediaPipe BlazeFace, работает локально).
2. Каждое лицо вырезается, сжимается до 48×48 в оттенках серого и по WebSocket уходит на Node-бэкенд (2304 байта на лицо).
3. Бэкенд выравнивает гистограмму и прогоняет лицо через CNN (ONNX Runtime, CPU, < 1 мс).
4. Вероятности усредняются по последним 8 кадрам; если уверенность ниже 0.4 — остаётся предыдущая эмоция. Эмодзи не мигает.

Всё работает локально, видео никуда не отправляется.

Если Node-бэкенд недоступен (например, в статическом деплое на Vercel), та же модель запускается
прямо в браузере через ONNX Runtime Web — в шапке появляется метка «в браузере».

Дообучение в этом режиме тоже есть, но облегчённое: свёрточная часть сети заморожена и выдаёт
128 признаков лица, а в браузере на своих кадрах обучается только последний слой 128 → 5
(`front/src/lib/browserTrain.js`). Снимки хранятся в IndexedDB этого браузера, дообученный слой —
в localStorage; на сервер ничего не уходит. Точность «до → после» считается на отложенных 20% кадров
каждой записи; на общем тесте в браузере она не проверяется. Полное дообучение всей сети и выгрузка
датасета — только с локальным бэкендом. Модель для браузера (`emotion_cnn_web.onnx` с выходом признаков
и `emotion_head.json`) создаёт `back/ml/export_browser.py` — запускайте его после `train.py`.

## Игра «камень, ножницы, бумага»

Карточка в правой панели: «Играть» → отсчёт 3-2-1 → фиксируется фигура, которую показывает рука
(кулак, знак мира, раскрытая ладонь), компьютер выбирает свою случайно и уже после этого. Счёт ведётся
до сброса. Фигуры определяются теми же правилами по точкам руки, что и жесты.

## Запуск

Нужны Node.js 20+ и Python 3.10+.

```bash
# 1. Бэкенд
cd back
npm install
npm start            # http://localhost:3001

# 2. Фронтенд (во втором терминале)
cd front
npm install
npm run dev          # http://localhost:5173
```

Откройте http://localhost:5173 и разрешите доступ к камере.

## Деплой на Vercel

Деплоится только `front/` как статический сайт (Root Directory = `front`, пресет Vite):

```bash
cd front
npx vercel --prod
```

## Обучение модели

Обученные веса уже лежат в `back/models/`. Чтобы обучить заново:

```bash
cd back/ml
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python train.py        # датасеты скачаются автоматически (~180 МБ)
```

- Датасеты: FER+ (картинки FER-2013 с исправленной разметкой Microsoft) и RAF-DB (фото «из жизни»); классы Disgust и Fear исключены → ~39 тыс. обучающих изображений 48×48 в оттенках серого.
- Копии датасетов на HuggingFace неофициальные; оригинальный RAF-DB распространяется только для исследований и учёбы.
- Валидация: 12% от train (стратифицированно); тест — официальные тестовые части FER+ и RAF-DB, только для финальной оценки.
- Дисбаланс классов — веса в `CrossEntropyLoss`. Аугментация: отражение, поворот ±10°, сдвиг, масштаб, яркость/контраст.
- Adam (lr 1e-3) + ReduceLROnPlateau, батч 64, до 60 эпох, ранняя остановка, seed 42.

Результаты на тестовых выборках (в обучении не участвовали):

| Тест | Старая модель (только FER-2013) | Текущая модель (FER+ и RAF-DB) |
|---|---|---|
| FER+ | 68.7% | **81.9%** |
| RAF-DB | 69.7% | **84.9%** |
| FER-2013 (старая шумная разметка) | 70.6% | 70.3% |

Общая точность на тесте FER+ и RAF-DB — 82.8%. Recall: радость 91%, удивление 90%, злость 83%,
грусть 77%, нейтрально 75%. Графики обучения и матрица ошибок — в `back/ml/reports/`.

## Свой датасет и дообучение

Базовая модель обучена на публичных датасетах. Собственный датасет собирается прямо в интерфейсе
(блок «Свой датасет и дообучение») и используется для дообучения:

1. Впишите имя того, кто в кадре, и выберите число кадров за запись (40 / 80 / 150).
2. Выберите эмоцию, покажите её в камеру, нажмите «Записать».
3. Повторите для остальных эмоций и других людей, при разном освещении и расстоянии до камеры.
4. Нажмите «Дообучить» — бэкенд запустит `ml/finetune.py`, покажет прогресс и сам подхватит новую модель.

Снимки (48×48, серые) хранятся в `back/ml/data/custom/<эмоция>/<человек>__<запись>_<кадр>.png`.
Кнопка «скачать .zip» выгружает весь датасет вместе с `labels.csv` (file, label, person, session).

Как считается результат:

- Последние 20% кадров каждой записи откладываются и в дообучении не участвуют — точность «до → после»
  на своих данных считается только по ним. Это всё равно оптимистичная оценка: отложенные кадры сняты
  в той же записи, что и обучающие. Честнее всего проверять на человеке, которого в датасете нет.
- Свои снимки смешиваются с частью обучающих данных, чтобы модель не разучилась на остальных людях;
  точность на общем тесте тоже показывается «до → после».
- Кнопка «вернуть базовую» откатывает к исходной модели.

## Ограничения

Модель предназначена для демонстрации и не оценивает реальное психологическое состояние человека.
Эмоции по одному кадру определяются неточно даже людьми, особенно грусть, злость и нейтральное лицо.

Эмодзи — системные (Unicode), детектор лиц — MediaPipe BlazeFace (Apache 2.0).
